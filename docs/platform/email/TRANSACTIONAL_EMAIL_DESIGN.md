# Transactional email design (Beautonomi)

Product notification email is sent through the **durable queue → Resend** path (`sendTemplateNotification` → `notification_delivery_queue` → `sendQueuedEmail`). Template copy lives in `public.notification_templates` (`email_subject`, `email_body`).

## Visual system

Hero templates follow the **542 / 738** inline-table shell:

| Token | Value | Usage |
|--------|--------|--------|
| Page background | `#f8fafc` | Outer table |
| Card max width | `640px` | Primary card |
| Header | `#111827` | Hero band |
| Accent wordmark | `#f9a8d4` | “Beautonomi” label |
| CTA | `#FF0077` | Primary button |
| Footer band | `#fdf2f8` / `#9d174d` | Legal / auto-generated note |

Constants are mirrored in `apps/web/src/lib/email/beautonomi-transactional-layout.ts` (`BEAUTONOMI_EMAIL_TOKENS`).

## Full HTML vs fragments

At enqueue time, `finalizeTemplateEmailHtml` runs on every template email:

- **Pass-through:** `email_body` is already a full document (`<!doctype` **or** `role="presentation"` + `max-width:640px`). Used for invoice/receipt/subscription reskins in SQL migrations.
- **Wrap:** Short HTML fragments (`<p>`, `<h2>`, etc.) are placed in the Beautonomi shell with hero title from `email_subject`, optional preheader, and a **single CTA** when a web URL is available.

**Admin rule:** Saving complete HTML in the admin SPA bypasses the wrapper. Fragments get the shell automatically.

## CTA URLs

- **Booking and most customer templates:** CTA `href` comes from runtime `resolvePushUrlFields(...).webUrl` (requires `NEXT_PUBLIC_APP_URL` + `notification_templates.url` with `{{booking_id}}`, etc.). Do not rely on `{{app_url}}` in booking confirm variables unless the sender adds it.
- **Provider billing / subscription SQL bodies:** May embed `{{app_url}}` where callers already supply it.

## Plain text

Queue payloads include **`text`** generated by `htmlToPlainText(finalHtml)`. Resend receives a real plain-text part (not duplicated push `body`).

## Channels

Email is only enqueued when **`'email' = ANY(notification_templates.channels)`** and the caller requests email. Tier 1 polish migrations re-add the email channel for keys that 608/691 left push-only (e.g. `payment_successful`).

## Localization

Per-recipient copy uses `notification_template_translations.email_subject` / `email_body` when present. Fragments in fr/ar are wrapped with the same English chrome unless you ship full localized HTML (long-term).

## Preview (staging / admin)

`POST /api/admin/notification-templates/[key]/preview-email` — substitutes sample merge tags, runs `finalizeTemplateEmailHtml`, returns `{ html, text, subject }` without sending.

## Supabase Auth email

Auth OTP/magic-link templates are configured in the Supabase Dashboard, not `notification_templates`. Examples under `supabase/email-templates/` use the same visual language as the transactional shell.

## Staging QA matrix

| Check | How |
|--------|-----|
| Gmail / Apple Mail | Send test queue email or use admin preview + Litmus |
| Plain-text part | Inspect Resend payload or preview API `text` field |
| CTA | Confirm `webUrl` resolves with `NEXT_PUBLIC_APP_URL` set |
| Wrapped vs full | Compare a legacy fragment key vs a Tier 1 migrated key |
| Locale | User with `fr`/`ar` profile receives translated `email_body` |
| SQL health | `enabled`, `'email' = ANY(channels)`, `email_body IS NOT NULL` for Tier 1 keys |
