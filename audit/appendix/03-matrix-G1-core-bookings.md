# Beautonomi provider-app audit — Phase 3, screen group G1 (feature matrix)

Read-only static audit. Screen paths are relative to `apps/provider/app/`; route paths are relative to `apps/web/src/app/api/` (each row's handler is `<path>/route.ts`). Helper paths are relative to `apps/provider/src/`.

Method of verification: every route file was located on disk and its handler content was read via targeted extraction (exported HTTP methods, `require*()` auth lines, `.from("table")`, `.rpc("name")`, third-party identifiers, `__tests__/` contents). Handlers that only delegate were followed into the delegated helper (noted in-row). "Static-verified" = handler content read; "UNVERIFIED" = not read (see last section).

Conventions: `req(role...)` = `requireRoleInApi([...])` (role-only, no permission). `perm(x)` = `requirePermission("x")`. `any(a,b)` = `requireAnyPermission([...])`. `auth` = `requireAuthInApi` (any signed-in user). Roles abbreviated: `O`=provider_owner, `S`=provider_staff, `SA`=superadmin, `C`=customer, `OB`=provider_onboarding. Tables listed are those referenced via `.from()` in the handler (R/W not separable by static grep; W is flagged where the row is a mutation route).

## Findings

1. **Role-only auth on schedule-mutating routes used by staff-schedule.tsx** — `POST /api/provider/shifts`, `PATCH /api/provider/shifts/[id]`, `DELETE /api/provider/shifts/[id]` use `requireRoleInApi(['provider_owner','provider_staff','superadmin'])` with no `manage_team` permission (`apps/web/src/app/api/provider/shifts/route.ts:310`, `provider/shifts/[id]/route.ts:96,200`). Any provider_staff can create/edit/delete dated shifts for any colleague. Contrast: the weekly-schedule sibling does gate with `manage_team` (`provider/staff/[id]/shifts/route.ts:77`, `provider/staff/[id]/shifts/[scheduleId]/route.ts:49`). Screen: `(app)/(tabs)/more/staff-schedule.tsx:594,607,641`.

Screen: `more/time-clock.tsx:189,200-201`. Only `PUT …/time-clock/[cardId]` is owner-gated (`:89`).
3. **POST /api/provider/sales trusts client-computed `subtotal`, `unit_price`, `discount_amount`** — `calculatedSubtotal = subtotal || items.reduce(...)` (`provider/sales/route.ts:615,683`), item `unit_price` is taken from the body and never re-resolved from the catalog, and `discount_amount` is unbounded (`:618,686`). Client sends `subtotal/discount_amount/tax_amount/tip_amount/total_amount/payment_status` at `(app)/(tabs)/sales.tsx:825-830,840` and `more/bookings/[id].tsx:2366-2372`.
